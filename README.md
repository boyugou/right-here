# Right Here website

The public site for [Right Here](https://github.com/boyugou/right-here), served by GitHub Pages from this
branch (`gh-pages`, root folder). Plain static files: no build step, no npm, no external fonts or CDNs.
This branch holds only the site; the app lives on `main`.

## Layout

| Path | What |
| --- | --- |
| `index.html`, `docs.html`, `privacy.html` | the pages |
| `404.html` | self-contained not-found page |
| `assets/` | `site.css`, `site.js`, the icon files, the social card, screenshots, menu glyphs |
| `i18n/<lang>.json` | the strings, one file per language (30, `en.json` is the authored source) |
| `robots.txt`, `sitemap.xml` | generated by `tools/set_base_url.py` |
| `tools/` | helpers that are not served as part of the experience (see below) |
| `.nojekyll` | tells Pages to serve the files as they are |

## The public address

Canonical, hreflang, `og:url`, `og:image` and the sitemap need absolute URLs. The committed pages carry
`https://boyugou.github.io/right-here/`. `tools/render_pages.py` writes relative ones (they work from any address, a
project sub-path and `file://`), so run this after every render and commit the result:

```sh
python3 tools/set_base_url.py https://boyugou.github.io/right-here/
```

This rewrites every element marked `data-abs="<path>"` (the path stays in the attribute, so you can run it again
with another address), regenerates `sitemap.xml` and `robots.txt`, and makes the home link of `404.html` absolute.
`python3 tools/set_base_url.py --reset` goes back to relative URLs and the placeholder
`https://example.invalid/right-here/` in the sitemap and robots file. Commit the result.

## How languages work

`assets/site.js` picks a language from `?lang=`, then the saved choice, then `navigator.languages`, then English,
and loads `i18n/<lang>.json`. The HTML carries the English text; a key a language file lacks keeps its English text.
`ar fa he ur` set `dir="rtl"`. In a string, text between backticks becomes `<code>`. Browsers do not allow
`fetch` of local files, so from `file://` only English shows (the page says so); over http(s) every language works.
The translations are machine-made. In October 2026 every language was read through against the English, the app's own words and
macOS's (the names of buttons, pages and menu items are the app's); a review by native speakers is still to come.

## Changing things

- A sentence: edit `i18n/en.json`, run `python3 tools/render_pages.py` (it fills the English text into the HTML) and
  then `python3 tools/set_base_url.py https://boyugou.github.io/right-here/`, translate the new or changed key in the
  other `i18n/*.json` files, run `python3 tools/check_i18n.py`. A key that no page uses any more has to leave
  `en.json` (and every language file); the check says so.
- The structure of a page: `tools/render_pages.py` holds the page templates.
- The privacy page says what `docs/appstore/PRIVACY.md` on `main` says, paragraph for paragraph (the `priv.*` keys).
  When that file changes, change the same keys in `i18n/en.json`, the date `POLICY_DATE` in `tools/render_pages.py`,
  and translate the changed keys. Keep the register of the existing privacy translations (formal "you" where the
  language has one).
- The icon: `uv run tools/make_icons.py <path to icon-1024.png>` rewrites `assets/icon.png`, the favicons, the
  touch icon and `assets/og-image.png`. Nothing else references the icon.
- Screenshots: `./script/preview_setup.sh <out.png> <language> [flags]` on `main` renders the setup window headlessly
  (it builds a throwaway package under `.build/preview`, so run it from a clone or worktree of `main` that you can build
  in, not from a checkout that something else builds in). Flags: `--tab overview|menu|checks|ai|worktrees|folders` (the
  section; Overview is the default), `--dark`, `--submenus` (every submenu of the Finder menu open), `--demo`,
  `--first-run`, `--set-up`, `--onboarding` (the three-step card, as when the Finder extension is off), `--gallery` (text
  checks, not for the site), `--minimum` and `--large-text`. Always use `--demo`, `--first-run` or `--set-up` for the
  site: they show canned data, the same on every Mac, with no path, last action, agent or terminal of the Mac that
  renders them, and the script stops when a canned text names that Mac's home folder or account. Without them the
  window shows that Mac's own state, which must not go on a public site. Each picture is rendered light and dark
  (`--dark`), and the site uses these three:
  - `en --first-run`: the very first run, no config file yet, the choice of terminal, editor and agents
    (`setup-first-*.png`).
  - `en --set-up`: just after Set Up, what it did and the three steps for the Finder extension (`setup-done-*.png`).
  - `ja --demo --tab menu`: the same section in Japanese (`setup-ja-*.png`).

  Each render is 860 points wide at 2x; resize it to 800 px wide (`sips --resampleWidth 800`). The icons of the menu's
  apps (Ghostty, Visual Studio Code, Xcode, TextEdit, Terminal) are read from the Mac that renders, so render on one that
  has them. Keep a light and a dark file the same size, and put the real size in the `width` and `height` of the `<img>`
  (`tools/check_site.py` compares them): the page reserves the space from the HTML. Pictures go on `index.html` only: its
  page-weight budget has room, the docs page's does not. Look at every render before it goes in: no truncated text or
  clipped icon, no home folder, account name or real time. The captions say that the setup is an example; when the
  window's wording changes, check them and the alt texts.
- The hero is `assets/demo.svg`, an animation drawn by hand: a right-click on a folder, the menu, Claude Code Here,
  and the command typed in a terminal. It has no script and no text to translate (the page's caption and alt text
  are translated). `tools/render_pages.py` writes `assets/demo-static.svg` from it, with the animation off, and the page
  shows that one when the visitor asks for reduced motion (a browser does not pass that preference into an SVG shown
  as an image). Its titles are the English ones of `tools/rh-menu-output.json`.
- The menu that a visitor can try (section "Try the menu") is generated from three files that
  `tools/capture_rh.py` writes from a build of `rh` on `main`:

  ```sh
  python3 tools/capture_rh.py <path to rh>
  ```

  It sets Right Here up in a throwaway home (a git repository `code/My App` with `Sources/main.swift`, Ghostty, Visual
  Studio Code, Claude Code and Codex), records `rh menu --json` and `rh menu` for the file, and for every action of that
  menu what `rh run <action> --dry-run --json` would do. It keeps only what holds no path of the Mac that runs it, and
  writes a copied path as if the home were `/Users/you`. `tools/render_pages.py` stops when the menu and the plans do
  not cover the same actions. The "Open With" list is whatever that Mac has installed. The glyphs in `assets/menu/` are
  exported from the Finder extension's asset catalog; any other icon is drawn as a plain tile. `assets/menu.js` opens
  the submenus and fills the panel; the page says the same without it (a preset is chosen).

## Checks before publishing

```sh
python3 tools/check_i18n.py     # keys, English text in the HTML, empty values, code spans, each file in its language
python3 tools/check_site.py     # links, ids, images and their real sizes, alt text, page weight, no path or account name of this Mac
```

The pages say what is built and what has not been checked on a real Mac (Shortcuts and Spotlight, presets in a real
terminal, iCloud Drive sync, the setup window's first run and its card against the real extension switch, iTerm2,
WezTerm and kitty). `docs/development/MANUAL_CHECKS.md` on `main` is the list of what has and has not been tried. When
one of those is checked, say so in `i18n/en.json` and in the docs, and translate the changed keys.
